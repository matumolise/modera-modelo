## Defectos demostrados

Seis contraejemplos fallaron contra la base: child_id booleano aceptado;
respuesta vinculada anterior a la oferta; respuesta persistida sin oferta
previa; reenvío del mismo evento duplicado; mismo offer_id con contenido distinto;
segunda respuesta que deja el JSONL incompatible con su lector canónico.
El séptimo test inicial era una prueba adicional de fallo del nuevo reemplazo
atómico, no un séptimo defecto reproducido: la base ni tenía esa operación.

Se corrige el tipo de child_id en ambos constructores y el orden temporal en
register_offer_response. Se valida la futura escritura con el lector existente
read_linked_offer_responses antes de publicar. El writer usa RLock, WriterLease
existente, archivo temporal fsync y os.replace; los bytes anteriores se conservan
como prefijo. Fallo de validación o de reemplazo deja el original intacto y
limpia el temporal. La reserva `.writer.lock` no se elimina ni se sustituye.

Reintentar el MISMO evento congelado con los mismos IDs/campos devuelve sin
reescribir; cambiar su contenido produce conflicto. Los constructores siguen
generando UUID al llamarse: volver a construir una oferta no es retry. El llamador
debe conservar y reenviar el objeto original. Una segunda respuesta con otro ID
se rechaza aun si tiene la misma selección. Se conserva la API legada sin
offer_id, que no aporta pares verificados para preferencias.

No se declara una transacción distribuida, respaldo, detección de archivo borrado
ni resistencia a pérdida de disco. El reemplazo atómico reescribe el archivo
completo; no es un store distribuido ni una evaluación de rendimiento. Procesos
competidores pueden recibir error de reserva y deben conservar el evento para
retry. El archivo existente inconsistente se rechaza; no se repara o migra.

## Política que NO está cerrada

El motor actual tiene solicitud voluntaria y descanso, ventana/espera de 60 min.
No hay disparador diurno ni coordinador compartido. El documento de ofertas
del 10/10 leído en sus primeras 90 líneas es explícitamente auditoría/propuesta;
la recuperación de chats no aportó aceptación de números o política completa.
No se adopta su 45 min, cupo 2, esperas, penalizaciones o vencimiento.

Una oferta registrada no prueba entrega; silencio no equivale a rechazo;
selección no equivale a realización. El escritor corregido no confirma esos
hechos. Android deberá conservar la oportunidad/offer_id entre canales y aportar
entrega/resultado. Antes de implementar el coordinador faltan reglas aceptadas
sobre oportunidad, arbitraje entre flujos, cupos/esperas y cierre/rechazos.
Este es un BLOQUEO DE POLÍTICA, no una función ya implementada ni una exclusión
de alcance decidida por el agente. Su aceptación corresponde a Matías/equipo.
